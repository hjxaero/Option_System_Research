# 旧项目规则概况

来源：`E:\Option_Sell_Research\.cursor\rules\*.mdc`

这些规则服务于旧项目 `Option_Sell_Research`，核心定位是 **MO 中证1000股指期权双卖策略研究与回测**。新项目只吸收其中的工程经验，不直接继承具体策略约束。

## 1. 项目主线

旧项目已经从多品种、多策略实验收敛为：

- 品种：中金所 MO 期权
- 策略：卖方双卖
- 数据：`snapshots/MO/*.parquet`
- 回测引擎：`DualSellRunner`
- 外部策略输入：`MarginLimitProvider`
- 主入口：`tests/run_factor_backtest.py`

这意味着旧规则大量绑定 `DualSellRunner`、保证金上限因子和 im_v2/im_v3/im_v5 因子，不适合作为新数据中台的全局规则。

## 2. 双卖回测引擎规则

旧规则强调：

- `DualSellRunner` 负责周期循环、建仓、对冲、到期平仓。
- `dual_sell_logic.py` 负责具体 action 构造。
- 因子只返回 `margin_used / NAV` 上限比例，范围 `[0, 1]`。
- 因子可以有 `on_period_start(period)` 钩子，用于周期边界重置内部状态。
- 回测报告必须显式写明建仓时间、因子版本、相关性计算方式和样本区间。

重要已知缺口：

- 每个到期周期只做一次初始建仓。
- 如果门控或对冲把仓位降到接近 0，即使门控恢复，也不会自动补回目标保证金规模。

## 3. 因子目录与边界

旧规则要求：

- 每个因子放在 `factors/<name>/`。
- 因子实现自包含，不依赖回测引擎。
- `factors/core/` 只放通用骨架，不放具体因子。
- 新因子从 `ideas/` 迁入正式目录前，需要接口清楚、至少一个测试、README 和登记。

禁止事项：

- `factors/*` import `backtest.engines`
- 因子内部实现完整建仓/对冲逻辑
- 大段复制旧 `strategy_v3.py` 且没有测试

## 4. 历史策略与归档

旧项目把单体策略放入 `archive/`，并规定：

- 新需求不要在 `archive/strategies/**/strategy_v3.py` 上继续实验。
- 保证金曲线或门控应进入因子包。
- 建仓、对冲、到期逻辑应进入 `DualSellRunner` 相关模块。
- 旧策略只用于复现和对照。

这个思想对新项目仍然有用：旧代码可以兼容调用，但不能让归档研究脚本继续成为主生产路径。

## 5. 文档与上下文规则

旧规则要求：

- 与用户沟通、项目文档、提交说明使用简体中文。
- 代码标识符、CLI 参数、CSV/parquet 列名使用英文。
- 策略/因子 spec 要先白话定义变量，再写公式。
- 敏感参数应在 README 开头显式列出。
- 每个重要因子或策略包维护 `README.md` 和 `CONTEXT.md`。
- 不把长聊天记录逐字贴入文档，只记录跨目录架构决策。

## 6. 实盘因子规则

旧规则把研究因子和实盘因子分开：

- 研究：`factors/im_vx_*`
- 实盘：`live_factors/<id>/`
- 实盘 registry 是唯一权威。
- 不把所有研究因子自动注册进实盘。
- 实盘跟踪只读取统一快照，不直接在跟踪进程里使用 `wait_update`。

这对新项目的启发是：研究、数据生产、实盘消费必须分层。

## 7. 可继承经验

新项目应该继承：

- 单一主线优先，不把实验脚本当生产路径。
- 数据、因子、引擎、实盘消费分层。
- 旧代码兼容但不继续扩展。
- 关键默认值必须写入文档。
- 新模块要有测试。
- 质量、风险和已知缺口要显式记录。

## 8. 不应继承的内容

新项目不直接继承：

- `DualSellRunner` 作为唯一主入口。
- `MarginLimitProvider` 作为唯一策略接口。
- im_v2/im_v3/im_v5 因子目录规范。
- `snapshots/MO/` 单一数据目录。
- 基于最新价的旧快照生成逻辑。
- 旧回测脚本路径和报告约束。
